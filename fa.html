مشکل

راه‌اندازی محلی، حدس‌هایی پخش‌شده در پست‌های انجمن است.

باید بدانید کارت گرافیکتان چقدر VRAM دارد، کدام مدل در آن جا می‌شود، چه پارامتری را برای سرعت عوض کنید، و خطای مبهم llama-server واقعاً چه معنایی دارد. این جعبه‌ابزار هر یک از این حدس‌ها را با چیزی جایگزین می‌کند که از دستگاه خودتان خوانده می‌شود.

  • قبل حدس زدن اینکه چه مدلی جا می‌شود بعد خواندن VRAM واقعی شما
  • قبل کپی کردن پارامترهای دیگران بعد بنچمارک کردنشان در برابر هم
  • قبل خطاهای مبهم زمان اجرا بعد متن خطا، عیناً

معماری

سه راه ورود، یک موتور

هر سه با یک کتابخانه‌ی مشترک کار می‌کنند، پس می‌توانید بدون یادگیری دوباره بین آن‌ها جابه‌جا شوید.

کتابخانه

Core

پکیج پایتونی که کار واقعی را انجام می‌دهد: شناسایی سخت‌افزار برای CPU، رم و VRAM کارت گرافیک، کنترل و نصب سرویس Ollama، چرخه‌ی عمر مدل‌ها، بنچمارک، محیط‌های پایتون برای مدل‌هایی که از دل اسکریپت اجرا می‌شوند، و یک دانلود‌منیجر با قابلیت resume.

MCPServer

همان ابزارها، در اختیار یک AI agent از طریق پروتکل Model Context Protocol. هدف را توصیف می‌کنید — یک مدل کدنویسی مناسب سیستم من نصب کن — و agent خودش مراحل را انتخاب می‌کند و عملیات‌های طولانی را در حین اجرا گزارش می‌دهد.

چه کاری انجام می‌دهد

چهار قابلیت، به همان ترتیبی که لازم‌شان دارید

این‌ها در کتابخانه زندگی می‌کنند، پس هر رابطی به آن‌ها می‌رسد. تصویرها از داشبورد است؛ یک agent همان توابع را صدا می‌زند.

01 System

اول دستگاه را بشناسید

یک اسکن کامل سخت‌افزار: پردازنده، ماژول‌های رم، کارت‌های گرافیک با VRAM، و دیسک‌ها با نوار مصرف. از اینجا شروع کنید — عدد VRAM تعیین می‌کند چه مدلی قابل بارگذاری است. نتیجه کش می‌شود، پس فقط یک بار منتظر می‌مانید.

02 Ollama

کنترل سرویس

وضعیت نصب و پروسه‌ی سرور در یک جا: روشن کردن، خاموش کردن، خواندن نسخه، و نصب Ollama از نصب‌کننده‌ای که روی دستگاه هست. وقتی اپ دسکتاپ ویندوز سرور را پشت سرتان دوباره راه می‌اندازد، همین به شما گفته می‌شود و توقفی که نگرفته نشان داده نمی‌شود.

03 Models

هر چه یک مدل لازم دارد

فهرست مدل‌های نصب‌شده و مدل‌های بارگذاری‌شده در حافظه، با اطلاعات، بارگذاری، توقف و حذف روی هر سطر. زیرشان فرم‌هایی برای اجرای یک پرامپت، ثبت یک فایل GGUF محلی، و ساختن نسخه‌ی کانفیگ‌شده از یک مدل — یک مدل جدید روی دیسک، بدون دست خوردن نسخه‌ی اصلی.

04 Benchmark

حدس زدن پارامترها را کنار بگذارید

یک مدل و چند پرامپت انتخاب کنید، چند مجموعه پارامتر تعریف کنید، و همه را اجرا کنید. کانفیگ را دستی از میان ۲۳ گزینه‌ی تولید بسازید یا یک فایل JSON را رها کنید. هر کانفیگ همه‌ی پرامپت‌ها را اجرا می‌کند و مدل قبل از هر اجرا پیش‌بارگذاری می‌شود تا زمان بارگذاری در زمان‌سنجی‌ها نیفتد.

قابلیت شاخص

یک مقایسه، نه یک نظر

بقیه‌ی قابلیت‌ها راحتی می‌آورند. این یکی عددی می‌دهد که وگرنه باید حدسش می‌زدید.

حکم اول می‌آید: کدام کانفیگ سریع‌تر تولید کرد و با چه اختلافی از نفر دوم. بعد سرعت تولید، سرعت پرامپت و زمان پاسخ، هر یک نسبت به بهترین مقدار گروه خودش مقیاس‌بندی شده، و در ادامه یک جدول خلاصه و جزئیات هر پرامپت.

هر اجرا چند دقیقه طول می‌کشد، پس در یک ترد پس‌زمینه انجام می‌شود — رابط قابل استفاده می‌ماند و رفرش کردن مرورگر آن را از دست نمی‌دهد. هر بار فقط یک مقایسه اجرا می‌شود، چون دو مقایسه‌ی همزمان برای یک GPU رقابت می‌کنند و هر زمان‌سنجی در هر دو را بی‌معنا می‌سازند.

آنچه اعداد را قابل استفاده می‌کند: seed را ثابت کنید و هر بار یک گزینه را عوض کنید. اگر دو کانفیگ در چند جا تفاوت داشته باشند، نمی‌توانید اختلاف را به هیچ‌کدام نسبت دهید.

راه ورود دیگر

یا هدف را توصیف کنید و agent کار را ببرد

همان جعبه‌ابزار، در اختیار یک دستیار هوش مصنوعی از طریق پروتکل Model Context Protocol.

می‌گویید یک مدل کدنویسی مناسب سیستم من نصب کن و agent سخت‌افزارتان را می‌خواند، مدلی را انتخاب می‌کند که در VRAM پیداشده جا می‌شود، دانلودش می‌کند، و تنظیماتش را بنچمارک می‌کند — ترتیب مراحل را خودش می‌چیند و هر کدام را توضیح می‌دهد. به همه‌ی توابع کتابخانه می‌رسد، از جمله آن‌هایی که داشبورد پوشش نمی‌دهد: محیط‌های پایتون، و صف دانلودی که آن‌ها را تغذیه می‌کند.

یک دانلود یا بنچمارک چند دقیقه طول می‌کشد، و این برای سکوت یک گفتگو زیادی طولانی است، پس این‌ها یک نوار پیشرفت زنده داخل خودِ گفتگو رسم می‌کنند: درصد کلی، یک سطر برای هر فایل یا هر کانفیگ، و نرخ انتقال جاری. بعد از رفرش هم سر جایش می‌ماند، چون وضعیتش روی دیسک است نه در حافظه.

دو کنترل، دو معنا: دکمه‌ی Cancel عملیات را تمام می‌کند و آن را برمی‌گرداند — دانلود لغو‌شده آنچه گرفته را حذف می‌کند. Stop تنها انتقال را معلق می‌کند و همه‌چیز را نگه می‌دارد، پس فشار دادن دوباره‌اش از همان‌جا که مانده ادامه می‌دهد.

راه‌اندازی

چهار دستور و اجرا می‌شود

پایتون ۳.۱۰ یا جدیدتر، به‌همراه Git برای گرفتن submodule هسته. این چهار دستور برای داشبورد است.

  1. 1 کلون با submodule

    bash 
    git clone --recurse-submodules https://github.com/ModelSetupHub/WebApp.git
cd WebApp

  2. 2 ساختن محیط مجازی

    bash 
    python -m venv .venv
.venv\Scripts\activate

  3. 3 نصب هسته، بعد وابستگی‌های وب

    bash 
    pip install -e ./core
pip install -r requirements.txt

  4. 4 اجرا

    bash 
    python app.py

بعد http://127.0.0.1:5000/ را باز کنید

مسیر agent را ترجیح می‌دهید؟ MCPServer به همین شکل نصب می‌شود و در هر کلاینت MCP ثبت می‌شود — از جمله Claude Desktop، که ابزار راه‌اندازی خودش را هم همراه دارد.

خط اول مرحله‌ی ۳ را رد نکنید

core یک submodule است، نه کپی کد. بدون pip install -e ./core هر درخواست با ModuleNotFoundError: No module named 'MSHCore' شکست می‌خورد.

یک موتور، سه راه ورود.
